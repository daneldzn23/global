# Stripe

## Why it's a reference

The industry-standard counter-example to generic AI-SaaS design —
technical B2B product, real UI as proof, restrained color, no
glassmorphism. Closest analog to what "premium, polished, confident"
(DESIGN.md's brand personality line) should look like for a technical
vendor rather than a consumer brand.

## What to steal

- **Real interface snippets embedded inline with copy** (a pricing
  table, an API response, a dashboard chart) instead of illustrated
  icons — every claim is backed by an actual screenshot of the thing
  being claimed, which is DESIGN.md's "show, don't tell" principle
  almost verbatim.
- **Precise, restrained gradients used structurally** (as section
  backgrounds or subtle dividers) rather than decoratively (glow blobs
  behind cards) — Stripe uses color with intent, which is the
  distinction DESIGN.md draws when it says glass/gradient/glow should
  be "used deliberately rather than decoratively."
- **Monospace/tabular numerals for data** (pricing, metrics, code) —
  a legitimate alternative to V1.4's "stat-grid with oversized numbers"
  pattern DESIGN.md flags as overused: same information, delivered
  with technical credibility instead of generic template weight.
- **No marquee/infinite-scroll logo wall.** Stripe's customer-logo
  sections use static, grouped, editorially-curated logo grids (often
  segmented by industry or use case) — directly solves the exact
  problem DESIGN.md flags with V1.4's scrolling partner-logo marquee.

## What NOT to copy

- Stripe's illustration system (abstract 3D gradient shapes) is
  distinctive to Stripe's brand and not something to imitate visually
  — the lesson to take is the *restraint and intent* behind their use
  of color, not the specific shapes.

## Where to look

- stripe.com homepage and the Payments/Billing product pages — how
  real UI screenshots are cropped and embedded directly in the copy
  flow instead of floating in generic device frames.
